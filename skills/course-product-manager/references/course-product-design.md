# 课程产品设计、交付与商业化

仅在任务涉及整体课程、大纲、运营或销售时读取相应部分。以下是可选设计维度与模板，不是每次交付清单；用户只要一课正文时，不追加产品方案。认知型课程的成果可以是有依据的解释、比较和条件判断，不强制变成操作作业。

## 从主题生成课程

当用户请求把主题发展为课程时，先把主题翻译成学员的问题与课程能承担的结果，再组织大纲；用户要求初版内容时继续写出样章。只请求课程设计或大纲时，交付有效设计，不自动扩成整门正文。

1. **主题解释**：把主题拆成可能的目标人群、应用场景、核心问题、能力结果和交付形态。
2. **方向收敛**：只有方向尚未收敛且会改变课程时，比较少量可行方向；用户已选定方向时直接推进。
3. **必要假设**：只补尚缺且会影响本轮设计的信息；已知受众和目标直接沿用，商业目标仅在相关时处理。关键未知无法自行解决时提出具体问题，不发送固定背景问卷。
4. **课程大纲初版**：输出模块、课时、每讲目标、关键内容、案例/演示、练习任务、作业产出和反馈方式。
5. **实际内容**：用户要求样章或课程初版时，写出第一讲或关键单元的完整内容。读取[内容理解与教学展开](explanation-development.md)，从材料形成解释；设计表中的案例和活动安排不算正文。开场、案例、练习和收束按课型选择，讲师经历仅在相关时采用。
6. **必要待定项**：只说明确实影响后续交付、尚待确认或验证的事项，不将已有信息再交用户确认。

## 定位与机会

先判断课程属性，再进入内容设计。

1. **课程类型判断**：概念认知、技能习得、案例拆解、工具训练、态度转变、认证准备、组织内训或商业转化。
2. **用户画像校准**：明确学员起点、焦虑、目标、已有替代方案、时间预算、学习阻力和付费触发点。
3. **产品定位一句话**：用“为谁，在什么场景下，通过什么路径，达成什么可验收结果”表达。
4. **差异化审查**：判断差异来自讲师经验、方法论、案例库、陪跑反馈、工具模板、社群资源还是交付确定性。
5. **承诺边界**：说明课程能解决什么、不能解决什么，避免过度承诺和不可验证结果。

## 学习路径

把课程从知识目录改造成能力路径。

1. **能力模型**：拆成认知、判断、操作、复盘、迁移五类能力，选出本课程真正负责的部分。
2. **模块坡度**：按学员起点与必要前提组织概念、机制、方法、示范、练习和迁移；熟悉问题可以作为入口，但不是固定顺序。不要从理念直接跳到缺少解释的操作。
3. **关键产出物**：为每个模块定义学员完成后的作品、清单、决策、方案、操作结果或复盘记录。
4. **练习与反馈**：每个关键能力至少配一个练习和一个反馈方式；没有反馈的技能课不算闭环。
5. **认知负荷**：把复杂概念拆成小节、案例、图示、对照表、模板和检查清单。
6. **表达层级**：同时检查课程级、模块级、段落级和句间级顺序。大纲合理不等于逐字稿连贯。
7. **迁移收束**：结尾帮助学员识别适用边界、变式场景、下一阶段路径或跨场景迁移，不用空泛的“升华”替代可执行迁移。

课程型知识库或对外学习材料应使用清晰的学习链路，例如：

```text
定位与学习目标
  -> 基础概念与原理
  -> 协作方法与任务协议
  -> 真实场景交付
  -> 判断验证与风险边界
  -> 方法沉淀与迁移
```

如果课程只剩“观点”和“怎么做”，优先补概念与原理层，而不是继续增加操作案例。

## 交付与运营

让课程能稳定交付，而不是只依赖讲师临场发挥。

1. **交付形态**：匹配内容难度与用户自驱力，判断录播、直播、训练营、工作坊或混合交付。
2. **节奏安排**：设计开营、预习、授课、作业、答疑、点评、复盘、结营和后续跟进。
3. **服务边界**：定义讲师、助教、社群、点评、资料、回放、退款或延期等边界。
4. **完成率设计**：设置低门槛首胜、阶段成果、同伴可见、提醒机制和卡点救援。
5. **成本约束**：评估讲师时间、助教成本、批改复杂度、社群维护和扩班风险。

## 转化与包装

把课程价值讲清楚，但不夸大。

1. **课程命名**：标题至少要让目标学员识别“这是为谁、解决什么场景、得到什么结果”中的两个关键维度，避免只有大词和情绪词。
2. **卖点结构**：按痛点、目标结果、方法路径、证据、适合/不适合人群、交付保障组织。
3. **证据链**：优先使用讲师经历、真实案例、可展示作品、方法框架、学员反馈或试学成果。
4. **公开课/先导课钩子**：开场先建立“这与我有关”和继续听的理由。可以使用问题、风险、机会、前后对比或认知落差，但不得为制造冲突而夸大痛点。
5. **产品阶梯**：必要时设计引流内容、体验课、正价课、进阶课、社群/咨询/企业内训的关系。

### 大纲与样课设计

用于决定教什么以及怎样组织。已有明确方向时不另列备选；假设和待定项只写实际缺失部分。

```markdown
## 课程设计
目标学员与起点：
课程要建立的理解或能力：
各部分为什么这样接续：

| 单元 | 承接的认识 | 本节要建立什么 | 采用的材料与教学作用 | 练习或理解检查 |
|---|---|---|---|---|
```

用户只要样课设计时，可以说明开场、解释、案例和练习怎样安排，并明确它是设计。用户还要样章时，在设计之后另写实际内容，不能把这张表或填好的栏目重命名为“第一讲样章”。

### 样章、课程正文与逐字稿

按学习过程实际成稿，不设固定栏目模板。概念应有可读的解释；关键案例写出本节需要的材料、变化、判断和结果；需要练习时给出可作答的材料、问题与适当反馈。步骤、图表、代码和讲师停顿可以承担教学功能。

交付时检查：读者只拿到这份内容，是否已有理解主要判断所需的信息；讲师是否还得自行补写核心讲解、案例或练习才能使用。如果还需要补写，继续完成正文，不能用备课说明代替。可录制逐字稿另按[讲述节奏](spoken-lesson.md)处理，阅读讲义不套时间码。

## 商业与交付边界

不得编造市场、转化、收入或学员反馈；不写“零基础到精通”等不可验证承诺。讲师履历不能替代学习价值与交付证据。受众和形态不明时不伪造精细售价或完整漏斗；按已知条件推进必要方案。训练营、社群、助教与退款安排只在任务涉及且有依据时设计，不默认所有课程都适合训练营。
