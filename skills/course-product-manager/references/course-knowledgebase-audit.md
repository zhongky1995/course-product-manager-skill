## 1. 适用范围与目标

在以下任务中使用本规范：

- 审查课程知识库、学习网站、学习应用或整套 Markdown/文档语料；
- 检查“内容是否完整”“学习路线是否合理”“入口是否太深”；
- 同时涉及课程结构、页面导航、前端体验和正文质量；
- 用户要求“整体检查”，或局部修复后反复指出同类教学问题。

目标不是只找坏链接、重复标题或缺失文件，而是判断一个目标学员能否找到正确起点，沿着合理坡度学懂内容，完成任务，并得到可验证的学习结果。

## 2. 六层验收模型

六层必须分别给状态和证据，不能互相替代。

| 层级 | 核心问题 | 主要证据 | 常见误判 |
|---|---|---|---|
| 资源完整性 | 文件、媒体、引用、链接是否齐全 | 文件清单、引用与链接检查 | “没有坏链，所以课程完整” |
| 课程产品结构 | 页面是否组成清晰的能力路径 | 受众、目标、课次角色、前置依赖、产出物 | “文件很多，所以课程丰富” |
| 内容解释质量 | 新手能否理解概念、机制与判断标准 | 逐页深审、案例、练习、认知桥 | “有定义和流程图，所以讲清楚了” |
| 学习路线语义 | 学员是否从正确入口进入并持续学习 | 入口测试、路径图、开始/继续状态 | “卡片可点击，所以入口没问题” |
| 应用体验 | 页面能否稳定浏览、操作与恢复状态 | 渲染、交互、响应式、错误状态测试 | “前端稳定，所以学习体验合格” |
| 真实学员验证 | 目标学员是否能独立理解和完成任务 | 可用性观察、试学、作业结果、访谈 | “专家审完了，所以新手一定能学会” |

每层状态只使用：`通过`、`有条件通过`、`不通过`、`待验证`。只有审查范围内六层全部通过，才可以给“整体通过”。

## 3. 页面角色分类

先给每个页面一个主要角色，再统计课程规模。一个页面可以有辅助角色，但必须有唯一主要角色。

| 页面角色 | 作用 | 是否计入核心课数 |
|---|---|---|
| 导学/入口 | 解释适用对象、起点、路径和学习方式 | 否 |
| 核心课 | 建立目标能力所必需的内容 | 是 |
| 进阶课 | 在核心能力上增加复杂度或新场景 | 单独统计 |
| 参考资料 | 按需查询的术语、清单、规范、附录 | 否 |
| 实验/练习 | 学员动手完成任务并获得反馈 | 单独统计 |
| 工作簿/作品集 | 承载阶段产出、证据或复盘 | 否 |
| 内部材料 | 保存产品假设、编辑策略、运营信息 | 否，且不对学员暴露 |
| 兼容入口/跳转页 | 维持旧链接或转向新结构 | 否 |

禁止用仓库文件总数表达课程课数。审查报告应同时给出“文件数”和“按角色分类后的课程规模”。

## 4. 全库审查流程

### 4.1 冻结范围

记录审查目录、版本、页面总数、应用入口和不在本轮范围内的材料。若审查期间发生批量修改，更新版本或重新冻结清单。

### 4.2 建立机器清单

可以自动统计：

- 文件、标题、层级、字数、引用、链接、资源路径；
- 重复标题、占位符、空页面、异常短页或异常长页；
- 导航目标、重定向、孤立页面和不可达页面；
- 高频模板句、术语首次出现位置和练习/案例标记。

这些统计只生成“风险候选”，不能直接判定内容好坏。标题相似可能是结构一致，也可能是模板泛化；字数少可能是过薄，也可能是合格入口页。

### 4.3 人工抽样与关键页深审

至少深审以下页面：

1. 所有导学和学习入口；
2. 每阶段第一课、最后一课和关键转场页；
3. 首次定义核心概念的页面；
4. 首次教授核心方法的页面；
5. 真实案例、实验、工作簿和验收页面；
6. 自动扫描发现的高风险页面。

若抽样发现系统性问题，不能只修样本；应定义模式并扫描全库同类内容。

### 4.4 课程架构判断

把页面放回“学员起点 → 概念与机制 → 方法 → 演示 → 练习 → 反馈 → 迁移”的能力路径。检查：

- 每一课是否承担明确教学任务；
- 前置概念是否在需要之前出现；
- 参考资料是否错误占据主学习路径；
- 阶段间是否存在新手无法跨越的能力断层；
- 对外页面是否暴露内部产品术语；
- 作业、练习、门槛和解锁条件是否互相矛盾。

只有课程架构确定后，才固化学习导航、卡片顺序和路由结构。

## 5. 学习入口语义测试

对每个主要入口执行以下测试：

| 测试 | 合格标准 |
|---|---|
| 可发现 | 目标学员无需知道内部目录名，就能在 30 秒内找到学习起点 |
| 正确起点 | 首次学习进入导学或第一节核心课，不落到阶段中部、结尾、参考页或兼容页 |
| 路径连续 | 页面结束后有唯一或清晰可选的下一步，不需要返回深层目录猜路径 |
| 状态区分 | “从头学习”和“继续学习”是两个明确动作，继续学习基于真实进度 |
| 心智预期 | 入口页说明适合谁、将完成什么、需要什么前置和大致路径 |
| 错误恢复 | 链接失效、进度缺失或权限不足时，能返回安全入口并得到解释 |

入口测试必须使用学习者语言描述结果，例如“新学员会被带到第 1 课”，不能只写路由地址正确。

## 6. 概念解释与案例跟踪测试

### 6.1 先区分三种材料

- **抽象解释**：定义、机制、流程或术语关系；可以准确，但不一定能让新手形成操作理解。
- **场景化说明**：加入真实背景或输入，但过程仍停留在抽象名词。
- **可跟踪案例**：同一输入经过每一步发生可见变化，学员能指出判断依据、错误点和验证方式。

“真实会议记录 → token → embedding → attention → 输出摘要”如果没有展示每一步具体发生了什么，仍然只是场景化说明。

### 6.2 可跟踪案例最小结构

1. **原始任务与输入**：使用学员能理解的真实材料。
2. **正确结果与错误结果**：先让学员知道最终差异。
3. **步骤变化**：对每一步给出输入、动作、输出和判断依据。
4. **中间表示声明**：不可观察时明确写“教学示意”或“假设示例”，不冒充真实内部日志。
5. **失败机制**：指出错误从哪一步产生、为什么会扩散到结果。
6. **验证动作**：学员如何检查输出与输入、规则或证据是否一致。
7. **迁移练习**：更换一个变量，让学员独立复现判断。

若底层机制无法直接观测，可以使用示意，但要分开表达：

- 已有研究支持的机制；
- 产品界面可观察到的行为；
- 为教学简化的示意；
- 仅用于帮助理解的类比。

### 6.3 新手复述测试

案例后让目标学员回答：

- 原始输入是什么？
- 每一步具体改变了什么？
- 结论依据来自哪里？
- 哪种错误结果看起来合理但不能接受？
- 自己遇到相似任务时先做什么、如何验收？

不能回答时，优先补过程和判断证据，不要只增加更多术语或类比。

## 7. 样板先行与批量改写闸门

先做一条最小完整路径：

```text
导学入口 -> 核心概念 -> 核心方法 -> 可跟踪案例 -> 学员练习 -> 验收与下一步
```

样板验收至少检查：

- 页面角色和顺序是否清楚；
- 新手是否看懂概念、过程和判断依据；
- 案例是否贯穿而不是片段拼接；
- 练习是否有输入、动作、产出和完成标准；
- 入口与下一步是否符合学习语义；
- 对外表达是否隐藏内部产品语言。

样板未通过时，只修样板和规则，不批量扩散。通过后，把样板中稳定的结构转成编辑规范，再按页面角色分批改写；每批保留人工抽查和回归测试。

## 8. 用户反馈升级规则

用户反馈本身是高优先级验收证据。按以下方式处理：

1. 把“太虚、跳了、不具体、入口太深”等自然语言翻译成可观察的失败模式；
2. 定位当前例子的最小问题，但同时搜索同角色、同模板和同机制页面；
3. 首次发现时报告局部范围；同类问题连续出现两次时，升级为全库扫描；
4. 不因已经做过“大检查”而拒绝升级，必须重新检查当时采用的验收标准是否过窄；
5. 报告受影响页面数、代表证据、统一修复规则、已修改样板和剩余风险。

## 10. 典型误判回归测试

每次更新此技能或执行全库审查后，用以下反例检查判断是否退化。

### 反例 A：技术通过但课程失败

所有文件、链接和页面都正常，但核心课和参考页混在一起，没有清晰能力路径。正确结论：资源完整性与应用技术可以通过，课程产品结构不通过，不能写整体通过。

### 反例 B：可点击但入口错误

首页“开始学习”按钮可点击，但跳到第二阶段第 3 课。正确结论：交互功能通过，学习入口语义不通过；应先建立导学和正确起点。

### 反例 C：有真实场景但仍然抽象

页面给出一段真实会议记录，随后只展示 `token -> embedding -> attention -> output`。正确结论：有场景、无可跟踪机制案例；必须展示具体输入变化、教学示意边界、错误结果和验证动作。

### 反例 D：自动指标看起来正常

页面字数、标题层级、案例标记和练习标记全部达标，但内容由重复模板填充，案例没有判断依据。正确结论：结构信号通过不等于内容解释通过，必须人工深审。

### 反例 E：局部反馈反复出现

用户先说一页“太虚”，修改后又在另一页指出同类问题。正确动作：将反馈升级为全库同类型扫描，而不是继续只修被点名页面。
